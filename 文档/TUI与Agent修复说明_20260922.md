# TUI 与 Agent 修复说明

本次修复对应《TUI全流程与Agent可用性检查_20260922》的四项问题。

## PublishAgent

- 注册内置 `research-publish` Agent，补充独立系统提示词，供 Publish 阶段的 Session 调用使用。
- 使用已有冻结实验快照生成报告，要求区分验证集和 ref-test、保留证据引用、不编造实验。
- 不开放外部工具：报告的完整输入已经通过快照提供。
- 保留现有报告校验和模板回退机制。

## LiteratureAgent

- 文献提取统一使用 `resolveEffectiveLLMConfig`，与其他研究 Agent 共用环境变量和 auth.json 凭据解析路径。
- 隔离测试验证：只有 auth.json、没有环境变量密钥时，文献提取模型也能正常初始化；测试不调用外部模型。

## Companion 检查点

- 恢复时读取最新审批决定，包括 rejected，不再把拒绝无条件替换为新的 pending。
- 拒绝追加实验预算：保留当前实验结果，继续最终模型确认，不追加训练。
- 拒绝搜索空间、最终模型、反思审核或报告发布：保持暂停，禁止越过关卡。
- 已拒绝且暂停的非预算检查点，可通过 `/approve` 修改决定；需求关键参数变化后，检查点签名会变化，允许重新确认。
- 搜索阶段仅在 NAS 实际完成后标记完成；报告发布确认移至导出之前。
- 反思要求人工确认时，在批准之前不标记 reflection 完成。

## 长任务、重连与取消

- TUI 为长操作发送 `Prefer: respond-async`，服务端返回 HTTP 202 和 operation ID。
- TUI 查询操作状态，训练总耗时不再受原有 90 秒或 10 分钟请求期限限制。单次启动/查询仍有网络超时。
- 同一项目、同一任务只允许一个研究操作运行。相同路径和请求参数可连接到运行中的操作；不同请求返回 409，防止重复训练。
- 请求断线不会自动终止已接受的后台操作。连接恢复后重新提交相同命令可以继续观察当前操作。
- Esc 或 `/abort` 请求后端取消，等待资源清理后再释放操作锁；重新进入页面后也可用 `/abort` 取消仍在运行的操作。
- 取消传递到研究 Session、数据准备和 Python runner。runner 支持终止进程树，覆盖 CV 子进程；相关 run 标记 failed，并记录用户取消原因，任务保持 paused。
- 无法确认后端状态时明确提示“可能仍在运行”，避免误报已停止。

新增接口：

```text
GET  /research/tasks/:taskID/operations/active
GET  /research/tasks/:taskID/operations/:operationID
POST /research/tasks/:taskID/operations/:operationID/cancel
```

未使用 `Prefer: respond-async` 的既有调用仍等待原始结果；也纳入相同的任务互斥和请求中断处理。

运行中 operation 的控制信息保存在当前服务进程内。本次支持服务存活时的客户端断线重连，不承诺服务进程崩溃后的原进程续跑；已有任务、run 和 artifact 仍由原持久化机制保存。

## 验证

最终相关服务/Agent/API 回归为 **92 通过、0 失败**；TUI 取消与循环定向回归 **4 通过、0 失败**。类型检查通过；Neo-Cast `npm test` 的 70 项 Node 测试及 Python unittest discovery 包装测试均通过。

- Publish 注册与提示词、Literature auth.json 凭据一致性。
- Companion 从 intent、搜索确认、预算拒绝、最终模型拒绝、报告拒绝到批准导出的完整服务流程。
- 后台操作收据、重复请求重连、冲突阻止、任务隔离和持久化 paused 状态。
- 取消必须等待资源清理；实际子进程和后代进程的终止。
- TUI 的 `/loop start` → HTTP 202 → 轮询 → Esc → 后端取消收据。
- OpenCode 类型检查、Neo-Cast 完整 `npm test`。

扩展运行 Agent、process 和 TUI render 测试得到 133 通过、6 失败；失败名称与修复前相同，涉及旧布局/onboarding、任务切换、候选选择和 slot-fill 断言，本次没有宣称这些历史失败已解决。真实 provider 的全链路调用仍需有效凭据验收。
