# NeoResearch 现有代码缺口分析

生成日期：2026-04-28

## 1. 分析范围

本文件分析当前目录：

```text
/Users/chengmingyue/human_agent_collaboration/research_working/idea/neo_research_for_tsf/neo-research
```

当前项目由两部分组成：

```text
neo-research/
```

本文重点分析 `neo_cast` 的现有代码缺口，并说明它与 `opencode` 参考源码之间尚未补齐的工程衔接。

## 2. 当前代码已经具备的基础

`neo_cast` 已经不是纯文档或概念稿，而是一个可运行的 Node.js CLI + Python TSF runtime。

已经具备：

- CLI 入口：`bin/neo-cast.js`
- 命令路由：`src/cli.js`
- LLM / mock candidate 生成：`src/llm.js`
- runtime 初始化：`src/runtime.js`
- Node -> Python bridge：`src/python-bridge.js`
- 数据协议：`py/dataset_contract.py`
- 数据准备与评估：`py/prepare_tsf.py`
- candidate renderer：`py/renderer.py`
- schema + smoke validation：`py/validate.py`
- 训练入口：`py/train.py`
- keep/discard runner：`py/runner.py`
- artifact export：`py/export.py`
- recipe factory：`py/factory/`
- action registry：`py/registry/`
- mutation policy：`py/search/`
- Node e2e tests：`test/e2e.test.js`
- Python unit tests：`py/tests/`

当前系统已经支持一个完整的本地闭环：

```text
prepare-data
  -> design
  -> validate / smoke
  -> train
  -> keep / discard
  -> export artifact
  -> ref-test final report
```

这说明当前代码已经达到 **可运行 MVP**，但距离完整 NeoResearch 系统还有明显缺口。

## 3. 测试与调试缺口

### 当前状态

`neo_cast/package.json` 已提供：

```json
{
  "scripts": {
    "test": "node --test test/*.test.js",
    "test:watch": "node --test --watch test/*.test.js",
    "dev": "node bin/neo-cast.js",
    "dev:debug": "node --inspect-brk bin/neo-cast.js",
    "design:mock": "node bin/neo-cast.js design --mode companion --max-candidates 3 --mock-llm",
    "doctor": "node bin/neo-cast.js doctor"
  }
}
```

并且有 VS Code 调试配置：

```text
neo_cast/.vscode/launch.json
```

支持：

- `design (mock, companion)`
- `design (mock, socratic)`
- `design (Claude API, companion)`
- `doctor`
- `runner status`
- `e2e tests`

### 实际缺口

直接运行：

```bash
npm test
```

当前结果不是全绿。实测结果为：

```text
pass 4
fail 2
```

失败项：

```text
design mock mode runs one candidate and updates results
runner ref-test evaluates the best artifact and updates metadata
```

失败原因主要是环境前置条件缺失：

```text
Runtime not initialized. Run: neo-cast init-runtime
Expected python: .../.neo-cast/runtime/.venv/bin/python
```

`doctor` 也显示：

```text
[FAIL] python3: Python 3.9.6 [system python3]
[OK] uv
[FAIL] runtime: Project runtime is not initialized
[FAIL] openai_compatible_api_key: OPENAI-compatible API key is not set
```

### 缺口判断

测试框架存在，但测试体验还不稳定。

主要问题：

1. e2e 测试依赖仓库本地 `.neo-cast/runtime/.venv`。
2. 部分测试依赖前序测试生成 runner state 和 best artifact。
3. 测试不是完全 hermetic，容易被本地状态影响。
4. `doctor` 使用系统 Python 检测时会暴露 Python 3.9.6，不初始化 runtime 时无法跑完整闭环。
5. 测试说明没有明确区分“无需 runtime 的单测”和“需要 runtime 的 e2e”。

### 建议补齐

建议拆分测试命令：

```json
{
  "scripts": {
    "test": "node --test test/*.test.js",
    "test:unit": "node test/python-unit.test.js",
    "test:e2e": "node --test test/e2e.test.js",
    "test:e2e:runtime": "node bin/neo-cast.js init-runtime && node --test test/e2e.test.js",
    "test:pack": "npm pack --dry-run",
    "test:publish": "npm publish --dry-run"
  }
}
```

并改造 e2e：

- 每个 e2e 测试使用临时 project dir。
- 测试内显式 init-runtime。
- 测试内显式 prepare-data。
- 不依赖仓库根目录历史 `.neo-cast` 状态。
- ref-test 测试自己先生成 best artifact。

## 4. npm 安装与发布缺口

### 当前状态

`neo_cast` 已具备 npm 包发布基础：

```json
{
  "name": "neo-cast",
  "version": "0.1.0",
  "bin": {
    "neo-cast": "./bin/neo-cast.js"
  },
  "engines": {
    "node": ">=20"
  }
}
```

`bin/neo-cast.js` 有 shebang：

```js
#!/usr/bin/env node
```

实测：

```bash
npm pack --dry-run
npm publish --dry-run
```

均可跑通。`npm publish --dry-run` 最终输出：

```text
+ neo-cast@0.1.0
```

说明它具备 npm 发布的基本条件。

### 实际缺口

#### 4.1 缺少 `.npmignore` 或 `files` 白名单

`npm pack --dry-run` 输出了警告：

```text
No .npmignore file found, using .gitignore for file exclusion.
Consider creating a .npmignore file to explicitly control published files.
```

当前 tarball 会包含很多不一定应该发布的内容：

- `.vscode/launch.json`
- `py/tests/`
- `test/`
- 架构分析文档
- 工作计划文档
- `load_dataset/load.csv`
- 多个中文说明文档

当前包大小：

```text
package size: 655.0 kB
unpacked size: 2.5 MB
total files: 81
```

这不算大，但发布内容边界不够干净。

#### 4.2 npm 自动修正 package.json

`npm publish --dry-run` 输出：

```text
npm auto-corrected some errors in your package.json when publishing.
Please run "npm pkg fix" to address these errors.

"bin[neo-cast]" script name bin/neo-cast.js was invalid and removed
```

这说明发布前需要让 npm metadata 处于无警告状态。

#### 4.3 发布前测试未全绿

当前测试不是全绿，发布前不能只依赖 `npm publish --dry-run`。

发布前至少需要：

```bash
node bin/neo-cast.js init-runtime
node bin/neo-cast.js doctor
npm test
npm pack --dry-run
npm publish --dry-run
```

### 建议补齐

建议在 `package.json` 增加 `files` 白名单，而不是依赖 `.npmignore`：

```json
{
  "files": [
    "bin/",
    "src/",
    "py/",
    "docs/runtime_deployment.md",
    "docs/blind_test_sidecar.md",
    "README.md",
    "NEO_CAST_MODES.md",
    "USAGE.md",
    "pyproject.toml",
    "uv.lock",
    ".env.example"
  ]
}
```

建议排除：

```text
.vscode/
test/
py/tests/
datasets (1)/
load_dataset/load.csv
neo_research_tsf_architecture*.md
neo_cast_解读.md
ROADMAP.md
DEVELOPMENT.md
AGENTS.md
```

同时新增发布脚本：

```json
{
  "scripts": {
    "prepack": "node bin/neo-cast.js --version",
    "pack:dry": "npm pack --dry-run",
    "publish:dry": "npm publish --dry-run"
  }
}
```

## 5. 领域系统能力缺口

当前 `neo_cast` 已有可运行闭环，但仍偏向：

```text
bounded recipe search / mutation loop
```

还没有完全升级为：

```text
Action-Space-Based Auto Model Construction
```

### 5.1 Research Intent 缺口

当前 `design --requirement "..."` 可以接收自然语言需求，但内部没有正式结构化的 `ResearchIntent`。

缺少：

```text
raw_text
objective
hard_constraints
soft_preferences
search_priors
reward_weights
report_preferences
```

影响：

- 用户偏好不能稳定转成搜索目标。
- hard constraints 与 soft preferences 没有分层。
- LLM prompt 里有需求文本，但系统状态里没有可审计的 intent。

建议新增：

```text
py/research_intent.py
py/schemas/research_intent_schema.json
src/intent.js
```

并让 `design` 流程从：

```text
raw requirement -> candidate
```

升级为：

```text
raw requirement -> ResearchIntent -> candidate / action trajectory
```

### 5.2 ActionTrajectory 缺口

当前保存的是最终 `CandidateRecipe`，而不是构建过程。

缺少类似：

```text
AddPreprocess(instance_norm)
SetEmbedding(patch)
SetBackbone(mlp)
SetFusion(shared)
SetLoss(huber)
```

影响：

- 难以说明 agent 是如何“构建模型”的。
- 难以对每一步 action 做成败归因。
- report 只能解释最终 recipe，不能解释 construction trajectory。

建议新增：

```python
ArchitectureAction
ActionTrajectory
```

并写入：

```text
.neo-cast/current_candidate.json
artifact/metadata.json
report.md
results.tsv 或独立 trajectory log
```

### 5.3 Model Compiler 缺口

当前有：

- JSON schema validation
- registry validation
- `build_model`
- smoke run

但还没有完整的 compiler layer。

缺少：

```text
CompiledRecipeGraph
shape_trace
module_graph
compatibility_trace
estimated_params
estimated_latency
preprocess/postprocess pairing trace
```

影响：

- `build_model` 能跑，但系统很难解释“为什么这个结构合法”。
- 对 branch / router / hybrid architecture 的扩展会变困难。
- artifact 中缺少完整 architecture graph。

建议新增：

```text
py/compiler/
  compile_recipe.py
  shape_trace.py
  graph.py
```

并让 `validate.py` 不只输出 valid/invalid，还输出 compiler diagnostics。

### 5.4 Reflection Loop 缺口

当前有 mutation policy：

```text
py/search/mutate.py
```

但它主要是基于 val metric 的启发式 mutation。

缺少：

- per-horizon diagnosis。
- per-variable diagnosis。
- trend / seasonality / shift 归因。
- failure tags。
- reflection summary。
- next action rationale。

影响：

- 系统现在更像“自动试验器”，还不像“自动研究员”。
- 下一轮候选生成对失败原因的利用不足。

建议新增：

```text
py/analysis/
  diagnose_result.py
  reflection.py
  failure_tags.py
```

并让 runner 每轮产出：

```json
{
  "hypothesis": "...",
  "observation": "...",
  "diagnosis": "...",
  "next_actions": [...]
}
```

### 5.5 Research Memory 缺口

当前主要有：

```text
.neo-cast/results.tsv
recent history passed into LLM
```

还没有真正的研究记忆系统。

缺少：

- short-term memory
- task-level memory
- cross-task meta memory
- failure pattern library
- action effectiveness statistics
- similar task retrieval

建议新增：

```text
.neo-cast/memory/
  experiments.jsonl
  action_stats.json
  failure_patterns.json
  task_fingerprints.json
```

### 5.6 Profile / Profiler 缺口

`dataset.v1` 已经有数据契约，但还没有完整 Time-Series Profiler。

缺少：

- trend strength
- seasonality strength
- stationarity / scale stability
- distribution shift
- cross-variable correlation
- horizon/context ratio
- missingness profile
- variable redundancy

影响：

- LLM 和 mutation policy 当前更多依赖 prompt 和历史结果。
- action prior 还不能真正 profile-conditioned。

建议新增：

```text
py/profiler.py
py/schemas/task_fingerprint_schema.json
```

## 6. Agent Runtime 与 opencode 集成缺口

当前 `opencode/` 是参考源码，不是 `neo_cast` 的实际依赖。

### 当前状态

`opencode` 是完整通用 agent 平台，包含：

- provider ecosystem
- TUI
- client/server
- plugin system
- tool abstraction
- permission policy
- session/message storage
- desktop/web/sdk

`neo_cast` 当前是独立轻量 CLI。

`neo_cast/package.json` 依赖很少：

```text
@anthropic-ai/sdk
@inquirer/prompts
commander
picocolors
```

没有直接复用 `opencode` 的：

- provider abstraction
- tool runtime
- plugin runtime
- permission model
- session/message store
- TUI
- server

### 缺口判断

当前两者关系是：

```text
opencode = 参考源码
neo_cast = 领域 MVP
```

还不是：

```text
opencode runtime + neo_cast tools
```

### 建议集成顺序

不建议直接把 `opencode` 整套搬进 `neo_cast`。

更稳的顺序：

1. 抽象 provider interface。
2. 抽象 session/message store。
3. 抽象 tool interface。
4. 把 `prepare-data / validate / runner / export` 包成 tools。
5. 加 permission policy。
6. 再考虑 TUI 或 client/server。

目标形态：

```text
NeoResearch Agent Runtime
  ├── ResearchIntent tool
  ├── DatasetProfiler tool
  ├── RecipeCompiler tool
  ├── ExperimentRunner tool
  ├── Reflection tool
  └── ReportGenerator tool
```

## 11. 总结

当前代码的最大优点是：

> `neo_cast` 已经把 TSF 自动实验闭环跑起来了。

当前代码的最大缺口是：

> 它还没有把 ResearchIntent、ActionTrajectory、CompilerGraph、ReflectionMemory 这些 AutoResearch 核心对象变成一等系统能力。

当前发布层面判断：

> npm 安装发布基本支持，但发布前需要清理包内容、修正 npm metadata warning，并确保 runtime 初始化后的测试全绿。

当前架构层面判断：

> `opencode` 目前还是参考源码，尚未变成 NeoResearch 的实际 agent runtime。短期不应强行合并，应该先有选择地吸收 provider、tool、session、permission 等基础抽象。
