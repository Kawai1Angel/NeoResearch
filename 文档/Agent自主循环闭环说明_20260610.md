# Agent 自主循环闭环说明（commit 99873fe）

> 本文档总结 commit `99873fe`（"feat: close the agent loop — Reflection drives HypoPlanner refresh, agents share state via DB+filesystem"）对 NeoResearch 自主研究循环（autonomous loop）的行为改动，作为团队内部交接/现状说明。

## 1. 总览：循环如何"闭环"

在这次改动之前，`HypoPlannerAgent` 只在循环开始时跑一次，产生的假设集合写入 `taskSpec.metadata.hypothesisPlan`，之后整个自主循环（多轮 DataAnalysis → ModelDesigner → Runner → Reflection）都复用同一批假设，`ReflectionAgent` 产出的 `nextHypotheses` 仅作为 markdown 文本展示，不会反向影响后续的假设规划。

这次改动把循环"闭合"了：**每完成一轮 TrainEval，`ReflectionAgent` 都会运行一次；其结构化结论会驱动 `HypoPlannerAgent` 重新规划假设集（保留/精炼/丢弃旧假设、追加新假设），新的假设集合写回数据库供下一轮 `ModelDesignerAgent` 使用**。Agent 之间不再通过内存对象互相传值，而是通过 **DB 表 `research_hypothesis`** 和 **`.neo-research/sessions/<task>/...` 下的文件**（`reflection_result.json`、`search_preferences.json`）交换上下文。

```
                     ┌─────────────────────────────────────────────┐
                     │                自主循环 (per iteration)        │
                     ▼                                               │
DataAnalysisAgent ──► 写 data_analysis_summary.md                    │
   │                  写 search_preferences.json (若 LLM 输出含       │
   │                  "## Search Preferences" 段落)                  │
   ▼                                                                  │
HypoPlannerAgent ──► 读 dataAnalysisSummary（磁盘）                    │
   │                  读 existingHypotheses（research_hypothesis 表）  │
   │                  读 previousReflection（最新 reflect_*/           │
   │                       reflection_result.json）                   │
   │                  读 search_preferences.json（若存在，覆盖默认       │
   │                       methodLibrary.preferences）                │
   │                  → LLM 生成/精炼假设列表                           │
   │                  → 写回 research_hypothesis 表（先删后插）         │
   ▼                                                                  │
ModelDesignerAgent ──► selectHypothesisFromList() 选定一个假设          │
   │                    → buildModelDesignerProposalFromHypotheses()   │
   │                      从该假设的 suggestedBackbones /               │
   │                      suggestedPreprocessing 中按可用组件库         │
   │                      选 backbone / preprocessing                  │
   ▼                                                                  │
Runner (smoke → run) ──► 写 runner_progress_jsonl (batch_progress)    │
   ▼                                                                  │
ReflectionAgent ──► 读 trainingCurve / 当前 candidateSpec / memory      │
   │                  → LLM 生成 7 字段结构化反思                        │
   │                  → 写 reflect_<ts>/reflection_result.json         │
   │                    （含 decision, nextHypotheses, ...）            │
   └──────────────────────► 触发下一轮 HypoPlannerAgent ────────────────┘
```

每轮迭代的关键顺序（`runAutonomousLoop` 内）：

1. 执行一次 TrainEval（DataAnalysis → ModelDesigner → Runner）。
2. 评估是否达到 stop 条件（target / plateau / time budget / crash streak）。
3. **无论是否停止**，先运行 `runReflectionAgent`（per-iteration reflection，非阻塞，失败不影响主流程）。
4. 若还有下一轮迭代：再运行 `runHypoPlannerAgent` 刷新假设集合，然后把任务状态恢复为 `searching`。
5. 若是最后一轮或满足停止条件，调用 `finishAutonomousLoop`（其中也会再跑一次收尾 reflection）。

## 3. HypoPlannerAgent 行为变化

### 旧行为

- `HypoPlannerInput` 直接接收 `dataAnalysis: DataAnalysisAgentResult`（内存对象）。
- `extractEvidenceSummary(dataAnalysis)` 从该对象中拼出 `searchBiases` / `warningCount` / `sourceArtifactIDs` 三句摘要。
- `orderedBiases(task, dataAnalysis)` 从 `dataAnalysis.searchBiases` 与 `task` 元数据合并取 bias。
- 假设对象（`HypothesisObject`）不含 `expectedOutcome` 字段。
- 默认搜索预算：`maxTrials ?? 12`，`noImprovementRounds ?? 3`。
- 假设规划只在循环开始执行一次，结果写入 `taskSpec.metadata.hypothesisPlan`。

### 新行为

#### 输入契约改为结构化 JSON（喂给 LLM 的 user prompt）

`buildHypoPlannerUserPrompt` 现在构造下面这个结构（对应 prompt 中描述的 4 个输入小节 + 额外上下文）：

```json
{
  "taskDefinition": { "...": "目标、指标、预算（buildTaskDefinition）" },
  "dataAnalysis": "<dataAnalysisSummary 文本，从磁盘读取>",
  "methodLibrary": {
    "...": "MODEL_RECIPE_LIBRARY，backbone/preprocessing 描述",
    "preferences": ["...若 search_preferences.json 存在则覆盖默认 preferences..."]
  },
  "previousReflection": {
    "decision": "continue | stop | request_human",
    "decisionReason": "...",
    "suggestedNextHypotheses": [{ "title": "...", "rationale": "...", "expectedSignal": "..." }],
    "reflectionNotes": "<reflection_notes.md 全文>"
  },
  "memoryLessons": [{ "outcome": "...", "lesson": "...", "modelDesign": {...}, "primaryMetric": 0.123, "recipeID": "..." }],
  "triedConfigurations": [{ "runID": "...", "status": "succeeded|failed", "val_avg_mse": 0.1, "error": "..." }],
  "existingHypotheses": [{ "statement": "...", "status": "pending|..." }],
  "instruction": "Review existingHypotheses in light of previousReflection ... retain / refine / drop ... add new ..."
}
```

第一轮迭代时 `previousReflection` 为 `null`，`existingHypotheses` 为 `null`，HypoPlanner 直接根据 `dataAnalysis` 生成全新假设集。

#### 假设生命周期：retain / refine / drop / add

`instruction` 字段明确要求 LLM：

- 对 `existingHypotheses` 中每条假设：
  - 若 `previousReflection` 未否定该假设 → **retain**（保留原样）；
  - 若 `previousReflection` 提供了新证据 → **refine**（修改 `statement` / `expectedOutcome`）；
  - 若 `previousReflection` 确认该假设已穷尽或被推翻 → **drop**（不再出现在新列表中）；
- 针对 `previousReflection.suggestedNextHypotheses` 中尚未被现有假设覆盖的方向 → **add**（追加新假设）。

返回值仍是 `{ "hypotheses": [...] }`，每条新增字段 `expectedOutcome: string`（"预期结果：哪个指标会如何变化，量化或半定量描述"）。`HypothesisObject` 类型新增：

```ts
export interface HypothesisObject {
  readonly id: string
  readonly statement: string
  readonly motivation: readonly string[]
  readonly expectedOutcome: string   // 新增字段
  readonly suggestedBackbones: readonly string[]
  readonly suggestedPreprocessing: readonly string[]
  readonly priority: "high" | "medium" | "low"
  readonly risk: string
  readonly testable: boolean
}
```

`hypothesisRules`（无 LLM 时的兜底规则库）的每条规则也补齐了 `expectedOutcome`，`buildHypothesesYaml` / `buildHypoPlanMarkdown` 同步输出该字段。

#### 数据来源变化

- `HypoPlannerInput.dataAnalysis: DataAnalysisAgentResult` → `HypoPlannerInput.dataAnalysisSummary: string`。
- `extractEvidenceSummary(dataAnalysisSummary)` 不再依赖 `DataAnalysisAgentResult` 对象，而是直接取 `dataAnalysisSummary` 文本的前 30 个非空行。
- `orderedBiases(task)` 不再接收 `dataAnalysis` 参数，仅从 `task` 的 `searchBiases` / `datasetProfile` 派生。
- `dataAnalysisSummary` 本身由 `loadDataAnalysisSummary(taskID)` 从磁盘的 `dataset_analysis_report` 产物文件读取（不再传内存对象）。

#### 持久化位置：从 `taskSpec.metadata.hypothesisPlan` 到 `research_hypothesis` 表

`updateTaskHypothesisPlan` 现在除了照旧把 `baselineStrategy` / `searchBiases` / `stopConditions` 写回 `taskSpec.metadata`，还会：

```ts
// 先清空该任务的旧假设
d.delete(ResearchHypothesisTable).where(eq(ResearchHypothesisTable.task_id, input.taskID)).run()
// 再批量插入新假设
d.insert(ResearchHypothesisTable).values(
  input.hypothesisPlan.hypotheses.map((h) => ({
    id: ResearchHypothesisID.ascending(),
    task_id: input.taskID,
    hypo_id: h.id,
    statement: h.statement,
    motivation: [...h.motivation],
    expected_outcome: h.expectedOutcome,
    suggested_backbones: [...h.suggestedBackbones],
    suggested_preprocessing: [...h.suggestedPreprocessing],
    priority: h.priority,
    risk: h.risk,
    testable: h.testable,
    status: "pending",
    time_created, time_updated,
  }))
).run()
```

即"全量替换"语义：每次 HypoPlanner 跑完，都用新假设集合整体覆盖旧表数据（不是按 id 增量 upsert）。

#### 默认搜索预算上调

```ts
const maxTrials = Math.max(1, Math.floor(budgetNumber(task, "maxTrials", "maxRuns") ?? 50))     // 12 -> 50
const noImprovementRounds = Math.max(1, Math.floor(budgetNumber(task, "noImprovementRounds", "maxNoImprove") ?? 20)) // 3 -> 20
```

## 4. ModelDesignerAgent 行为变化

### 旧行为

`selectHypothesisForDesign(plan: ExperimentPlan | undefined)` 直接从 `ExperimentPlan.hypotheses`（即 `taskSpec.metadata.hypothesisPlan`）按优先级（high → medium → low，且 `testable === true`）选出一个假设，但**没有**统一的"从假设到 backbone/preprocessing 选择"的逻辑——这部分由别处（domain proposal / LLM）隐式承担。

### 新行为

#### 假设选择逻辑抽出为通用函数

```ts
export function selectHypothesisFromList(hypotheses: readonly HypothesisObject[]): HypothesisObject | undefined {
  if (hypotheses.length === 0) return undefined
  const priorityOrder: readonly HypothesisObject["priority"][] = ["high", "medium", "low"]
  for (const priority of priorityOrder) {
    const hypothesis = hypotheses.find((item) => item.testable && item.priority === priority)
    if (hypothesis !== undefined) return hypothesis
  }
  return hypotheses.find((item) => item.testable) ?? hypotheses[0]
}

export function selectHypothesisForDesign(plan: ExperimentPlan | undefined): HypothesisObject | undefined {
  return plan === undefined ? undefined : selectHypothesisFromList(plan.hypotheses)
}
```

`selectHypothesisForDesign` 现在只是 `selectHypothesisFromList(plan.hypotheses)` 的薄包装，逻辑本体复用同一函数。`service.ts` 中 `runAutonomousIteration` 通过 `experimentPlanFromDB(task, hypotheses)`（`hypotheses` 来自 `listHypotheses` / `research_hypothesis` 表）构造 `ExperimentPlan`，再调用 `selectHypothesisForDesign`。

#### 新增组件库 + "从假设直选 backbone/preprocessing"

```ts
export interface ModelDesignerComponentLibrary {
  readonly backbones: readonly string[]
  readonly preprocessing: readonly string[]
  readonly embeddings: readonly string[]
  readonly losses: readonly string[]
  readonly optimizers: readonly string[]
  readonly schedulers: readonly string[]
}

export function buildModelDesignerComponentLibrary(input: {
  readonly actionRegistry: Record<string, Record<string, { readonly bridgeSupported: boolean }>>
  readonly bridgeOnly?: boolean
}): ModelDesignerComponentLibrary
```

从 action registry 中按类别（`backbone` / `preprocessing` / `embedding` / `loss` / `optimizer` / `scheduler`）枚举可用名称；若 `bridgeOnly` 为真，仅保留 `bridgeSupported: true` 的项。

```ts
export interface ModelDesignerInput {
  readonly task: ResearchTask
  readonly dataAnalysisSummary: string
  readonly hypotheses: readonly HypothesisObject[]
  readonly componentLibrary: ModelDesignerComponentLibrary
}

export interface ModelDesignerHypothesisProposal {
  readonly selectedHypothesis: HypothesisObject
  readonly proposal: DomainCandidateProposal
}

export function buildModelDesignerProposalFromHypotheses(
  input: ModelDesignerInput,
): ModelDesignerHypothesisProposal | undefined
```

逻辑：

1. `selectHypothesisFromList(input.hypotheses)` 选一个假设；没有假设则返回 `undefined`。
2. `firstAvailable(hypothesis.suggestedBackbones, lib.backbones)` —— 取假设建议的 backbone 中第一个在组件库里可用的；若一个都不可用，退化为组件库第一个。`suggestedPreprocessing` 同理。若两者都拿不到任何值，返回 `undefined`。
3. `loss` / `optimizer` / `scheduler` 分别优先选 `mse` / `adamw` / `cosine`（若库中存在），否则取库中第一个。
4. 拼出一份最小 `candidateSpec`（`recipe_schema_v1`）：

```json
{
  "recipeVersion": "recipe_schema_v1",
  "hypothesis": "<H1: statement>",
  "preprocessing": { "actions": [{ "type": "<chosenPreprocessing>" }] },
  "backbone": { "type": "<chosenBackbone>" },
  "trainingStrategy": {
    "loss": { "base": "mse", "horizonWeighting": "uniform" },
    "optimizer": { "type": "adamw", "lr": 0.001, "weightDecay": 0 },
    "scheduler": { "type": "cosine", "warmupSteps": 0 },
    "regularization": { "dropout": 0.1 },
    "budget": { "maxEpochs": 30, "timeBudgetS": 600, "batchSize": 64, "patience": 5, "seed": 42 }
  }
}
```

5. `rationale` 由 `buildRationaleFromHypothesis` 生成，引用假设的 `id`、`statement`、`expectedOutcome`、前两条 `motivation`、`risk`：

```
Hypothesis H2: <statement>. Selected backbone "dlinear" and preprocessing "series_decomposition" to test this hypothesis.
Expected outcome: <expectedOutcome>. Evidence: <motivation[0]> <motivation[1]> Risk: <risk>
```

6. `riskLevel`：假设 `priority === "high"` → `"medium"`，否则 `"low"`；`approvalStatus: "auto_approved"`，`generatedBy: "heuristic"`。

> 注：`buildModelDesignerProposalFromHypotheses` / `buildModelDesignerComponentLibrary` 是本次提交新增的纯函数（已有单测覆盖），在 `service.ts` 主流程中尚未直接看到调用点——现有 `runAutonomousIteration` 仍主要走 `selectModelDesignerCandidate` + LLM/domain proposal 路径，`selectedHypothesis` 通过 `buildModelDesignerTaskFingerprint` 影响 LLM 的候选生成上下文。这两个新函数提供了"假设 → recipe 直选"的备用/简化路径。

## 5. ReflectionAgent 行为变化

### 旧行为

`ReflectionAgentResult.llm` 只有：

```ts
llm: {
  status: "disabled" | "not_configured" | "used" | "failed"
  model?: string
  text?: string
  error?: string
  usage?: LLMTokenUsage
}
```

LLM 输出（如有）是一段自由文本 `text`，没有结构化字段；`decide()` 在"无 plateau、无 hypotheses"时给出固定理由 `"尚未达停止条件，建议沿用现有搜索策略继续。"`。

### 新行为

#### 新增 7 字段结构化 LLM 输出

```ts
export interface ReflectionLLMAnalysis {
  readonly trainingHealthAssessment: string   // 训练过程是否健康：收敛性、震荡、NaN，结果是否可信
  readonly hypothesisValidation: string       // 原假设是否被结果支持：yes/no/partial + 说明
  readonly attributionAnalysis: string        // 性能提升/下降的具体归因（架构/训练因素）
  readonly historicalComparison: string       // 本轮在整体研究轨迹中的位置，与历史最优对比
  readonly modelDesignReflection: string      // 哪些架构/训练/数据处理选择需要重新审视
  readonly nextStepRecommendation: string     // continue / modify / abandon / pivot 及理由
  readonly distillableMemory: string          // 给后续 agent 的自包含摘要：尝试了什么、结果、建议、风险
}
```

`ReflectionAgentResult.llm` 新增 `structured?: ReflectionLLMAnalysis` 字段（与原有 `text` 并存）。

System prompt（`buildReflectionLLMSystemPrompt`）要求 LLM 返回**仅含这 7 个 key 的单个 JSON 对象**，每个值 1-4 句话；并给出明确规则：若 `trainingHealthAssessment` 表明训练不稳定（loss 震荡/发散/NaN），`nextStepRecommendation` 不应基于本轮结果建议放弃假设，而应先建议稳定训练（降低 `learning_rate`、增加 `warmup_ratio`、启用梯度裁剪）再重跑。

`parseReflectionLLMStructured(text)` 用正则 `/\{[\s\S]*\}/` 提取 JSON，校验全部 7 个字段均为非空字符串，否则返回 `undefined`（此时 `result.llm.structured` 缺失，仅保留 `text`）。

#### LLM 输入上下文（user prompt）

`buildReflectionLLMUserPrompt` 现在由以下来源拼装：

- `taskObjective`：指标名 + 方向 + 可选 target/description；
- `originalHypothesis`：最近一次 candidate 的 `rationale`；
- `experimentDesign`：最近一次 candidate 的 `candidateSpec`（架构 + 训练配置 JSON）；
- `experimentResults`：`analyzeReflection` 的统计结果（best/latest metric、effective/ineffective changes、failures...）；
- `trainingCurve`：从 `runner_progress_jsonl` 产物中通过 `extractTrainingCurve` 提取的 `{ epoch, valLoss, horizon?, elapsedS? }[]`（依赖本次提交在 `train.py` 中新增的 `batch_progress` 事件，提供更细粒度的训练曲线）；
- `historicalExperimentMemory`：最近 2 条 memory lesson + 历史最佳 metric 对应的 lesson。

#### `decide()` 的微调

无 plateau 且无 `nextHypotheses` 时的 `continue` 理由从固定中文句子改为空字符串 `""`（即不再给出预设理由文案，留给上层/LLM 的结构化输出承载这部分信息）。

#### 写入磁盘：`reflection_result.json`

每次 `runReflectionAgent` 执行完毕，会在 `.neo-research/sessions/<taskID>/reflect_<ts>/` 下写：

- `reflection_notes.md`
- `next_experiment_plan.md`
- `failure_log.md`
- `reflection_result.json`：

```json
{
  "reflectRunId": "reflect_1718000000000",
  "taskID": "...",
  "decision": "continue | stop | request_human",
  "decisionReason": "...",
  "nextHypotheses": [{ "title": "...", "rationale": "...", "expectedSignal": "..." }],
  "plateauStreak": 0,
  "succeededRuns": 3,
  "failedRuns": 0,
  "bestMetric": 0.123,
  "reflectionNotesMarkdown": "...",
  "nextExperimentPlanMarkdown": "...",
  "failureLogMarkdown": "..."
}
```

注意：写入磁盘的 `reflection_result.json` 中**不包含** `ReflectionLLMAnalysis` 的 7 个结构化字段本身（`structured` 字段未序列化到该 JSON），只包含 `analysis`（规则计算结果）的摘要 + 三份 markdown 全文。7 字段结构化反思主要通过 `ReflectionAgentCompleted` 事件的 metadata（`llmNarrative` 取自 `result.llm.text`）和 memory lesson（`buildReflectionMemoryLesson`，会引用 `structured.distillableMemory` 的前 400 字符）传播。

## 6. 跨 Agent 状态共享机制

### 6.1 `research_hypothesis` 表

迁移文件：`opencode/packages/opencode/migration/20260607000000_research_hypothesis/migration.sql`

```sql
CREATE TABLE `research_hypothesis` (
    `id` text PRIMARY KEY NOT NULL,
    `task_id` text NOT NULL REFERENCES `research_task`(`id`) ON DELETE cascade,
    `hypo_id` text NOT NULL,
    `statement` text NOT NULL,
    `motivation` text NOT NULL,           -- JSON 数组
    `expected_outcome` text NOT NULL,
    `suggested_backbones` text NOT NULL,  -- JSON 数组
    `suggested_preprocessing` text NOT NULL, -- JSON 数组
    `priority` text NOT NULL,
    `risk` text NOT NULL,
    `testable` integer NOT NULL,
    `status` text NOT NULL DEFAULT 'pending',
    `time_created` integer NOT NULL,
    `time_updated` integer NOT NULL
);
CREATE INDEX `research_hypothesis_task_idx` ON `research_hypothesis` (`task_id`);
CREATE INDEX `research_hypothesis_status_idx` ON `research_hypothesis` (`status`);
```

对应 Drizzle 定义在 `research.sql.ts` 的 `ResearchHypothesisTable`，`motivation` / `suggested_backbones` / `suggested_preprocessing` 以 `mode: "json"` 存储为字符串数组。`schema.ts` 新增 `ResearchHypothesisID`（`Identifier.schema("researchHypothesis")` brand 类型）。

读写入口：

- 写：`updateTaskHypothesisPlan`（HypoPlanner 跑完后调用）—— **先 delete 该 task 的全部行，再批量 insert**。
- 读：`listHypotheses(taskID)` —— 按 `time_created` 升序返回全部行，映射为 `HypothesisObject[]`，供 `experimentPlanFromDB` 构造 `ExperimentPlan` 并交给 `selectHypothesisForDesign`。
- HypoPlanner 自身在重新规划前，也会读一次 `existingHypothesesRaw`（仅取 `statement` + `status`）作为 prompt 中的 `existingHypotheses`。

### 6.2 `.neo-research/sessions/<taskID>/reflect_<ts>/reflection_result.json`

- 写入方：`runReflectionAgent`，每轮迭代结束（以及 `finishAutonomousLoop` 收尾时）各写一份，目录名按时间戳 `reflect_<Date.now()>` 递增。
- 读取方：
  - `runHypoPlannerAgent`：扫描 `sessions/<taskID>/` 下所有 `reflect_*` 目录，按目录名倒序找到**最新**一份 `reflection_result.json`，解析出 `{ nextHypotheses, reflectionNotesMarkdown, decision, decisionReason }` 作为 prompt 中的 `previousReflection`。
  - `runAutonomousIteration`：同样扫描最新 `reflection_result.json`，取 `nextHypotheses` 的 `title` 列表（`reflectionHypotheses`）和 `reflectionNotesMarkdown`（`previousReflectionNotesMarkdown`），喂给 `buildModelDesignerTaskFingerprint`。

### 6.3 `.neo-research/sessions/<taskID>/analysis/search_preferences.json`

- 写入方：DataAnalysis 阶段的 `generateLLMQualitativeAnalysis`。LLM 输出现包含新增的 `## Search Preferences` 段落（3-5 条 backbone/preprocessing 搜索建议，英文，data-driven）；`parseSearchPreferencesFromQualitative(text)` 用正则 `/##\s*Search Preferences\s*\n([\s\S]*?)(?:\n##|$)/` 提取该段落，按行去除项目符号、过滤长度 >10 的行，最多取 8 条。若非空，写入：

```json
["Prefer dlinear as a baseline given the strong trend component (trendVarianceShare > 0.6).", "..."]
```

路径：`.neo-research/sessions/<taskID>/analysis/search_preferences.json`。

- 读取方：`loadLLMSearchPreferences(workspaceRoot, taskID)`（在 `generateLLMHypotheses` 中调用）。若文件存在且为字符串数组，则在 `buildHypoPlannerUserPrompt` 中用它**整体替换** `MODEL_RECIPE_LIBRARY.preferences`（而不是与默认偏好合并）：

```ts
methodLibrary: llmSearchPreferences && llmSearchPreferences.length > 0
  ? { ...MODEL_RECIPE_LIBRARY, preferences: llmSearchPreferences }
  : MODEL_RECIPE_LIBRARY,
```

## 7. 支撑性改动（简述）

- **搜索预算默认值上调**：`maxRuns` 12 → 200（`clampMaxRuns` 类逻辑：`Math.max(1, Math.min(Math.max(budgetMaxRuns ?? 50, 50), 200))`）；HypoPlanner 的 `maxTrials` 默认 50，`noImprovementRounds` 默认 3 → 20；自主循环 `maxIterations` 默认 50（cockpit 触发请求从 10 改为 50，部分内部路径为 `maxIterations + 5`）；`maxCrashStreak` 默认 3 → 5。整体目的是支持更长的自主搜索运行。
- **新增 `updateTaskBudget` service 方法 + `PATCH /research/tasks/:taskID/budget` REST 路由**（`server/routes/instance/research.ts`），允许动态调整任务预算。
- **`prepare_tsf.py` / `dataset_contract.py`**：现在会先物化一份 train-only 的 CSV 切分，数据分析（profile）基于该切分计算，不再扫描完整序列（加快 DataAnalysis 阶段）。
- **`train.py`**：训练过程中新增 `batch_progress` 事件输出，为 `extractTrainingCurve` 提供更细粒度的训练曲线数据点（供 ReflectionAgent 的 `trainingHealthAssessment` 使用）。
- **Cockpit (`research-cockpit.tsx`)**：
  - 输出环形缓冲区从 30 行扩大到 500 行（注释说明：`full` 阶段一次运行可产生远超 30 条 `epoch_end` 行，小缓冲区会在 Reflection/HypoPlanner 跑之前就把早期训练历史挤掉）。
  - design / runner / reflection / hypoplanner 的流式输出按时间顺序合并展示在同一条 `designLLMLines` 流中（按事件 id 排序合并），而不是分开的多个面板。
