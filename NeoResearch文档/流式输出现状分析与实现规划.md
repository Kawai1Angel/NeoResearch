# NeoResearch TUI 流式输出：现状分析与实现规划

> 问题：两种交互模式（Socratic / Companion）下，Agent 执行过程的实时输出是否已在 TUI 界面流式展示？
>
> 结论：**未实现。** 当前 TUI 只显示最终状态，Python 进程的逐行训练日志在 Node 侧被全量缓冲后丢弃，没有任何实时进度传递到界面。

---

## 1. 现状：三个断点

### 断点 1 — `Process.run` 全量缓冲（`src/util/process.ts:113`）

```typescript
// 当前实现：等进程结束，一次性返回所有 stdout/stderr
const out = await Promise.all([
  proc.exited,
  buffer(proc.stdout),   // ← 全量缓冲，进程结束才可读
  buffer(proc.stderr),
])
```

Python 进程已经在逐行输出结构化 JSON：

```jsonl
{"event": "stage_start", "stage": "smoke", "candidate_id": "recipe_tcn_seasonal_llm"}
{"event": "epoch_end", "horizon": 96, "epoch": 1, "val_loss": 0.719233}
{"event": "timeout", "elapsed_s": 221.721, "budget_s": 60}
{"event": "smoke_eval_done", "val_avg_mse": 0.721511}
{"event": "artifact_ready", "run_id": "20260504-191825-hbrp"}
```

但 Node 侧通过 `buffer()` 等待整个进程结束后才读取，**中间过程全部丢失**。

---

### 断点 2 — `event.ts` 没有 Runner Progress 事件

`src/research/event.ts` 定义的事件全部是离散状态变更（任务创建/更新、Run 创建/更新、NAS 迭代完成等），没有任何实时进度类事件：

```typescript
// 现有事件：全是状态变更，没有实时进度
export const Event = {
  RunCreated: ...,
  RunUpdated: ...,
  NASIterationCompleted: ...,
  // ← 完全没有 RunnerProgressLine / EpochEnd / StageStart 等
}
```

TUI 的刷新触发集合 `researchRefreshEventTypes`（`research-cockpit-data.ts:191`）也只包含这些状态变更事件，没有进度事件的位置。

---

### 断点 3 — TUI `streamLines` 只渲染最终状态（`research-cockpit.tsx:2223`）

`streamLines` memo 的渲染逻辑：

```
latestRun 有结果  →  显示 run 状态（succeeded / failed）
pendingApproval  →  显示 approval 提示
socraticClarification  →  显示澄清问题槽位
其他             →  显示 idle 占位文案
```

没有任何地方消费实时训练日志。两种交互模式下的"执行中"状态，用户只能看到 spinner + busy 文字，看不到 epoch loss、训练进度、阶段切换等信息。

## 2. 需要实现的三层改动

### Layer 1：进程层 — `src/util/process.ts`

新增 `runStreaming` 函数，支持逐行回调：

```typescript
export interface StreamingRunOptions extends RunOptions {
  onStdoutLine?: (line: string) => void
  onStderrLine?: (line: string) => void
}

export async function runStreaming(
  cmd: string[],
  opts: StreamingRunOptions = {},
): Promise<Result> {
  const proc = spawn(cmd, {
    ...opts,
    stdout: "pipe",
    stderr: "pipe",
  })

  const stdoutLines: Buffer[] = []
  const stderrLines: Buffer[] = []

  // 逐行读取 stdout，每行触发回调
  proc.stdout?.on("data", (chunk: Buffer) => {
    stdoutLines.push(chunk)
    const text = chunk.toString()
    for (const line of text.split(/\r?\n/).filter(Boolean)) {
      opts.onStdoutLine?.(line)
    }
  })

  proc.stderr?.on("data", (chunk: Buffer) => {
    stderrLines.push(chunk)
    const text = chunk.toString()
    for (const line of text.split(/\r?\n/).filter(Boolean)) {
      opts.onStderrLine?.(line)
    }
  })

  const code = await proc.exited
  return {
    code,
    stdout: Buffer.concat(stdoutLines),
    stderr: Buffer.concat(stderrLines),
  }
}
```

**改动范围：** 只新增函数，不修改现有 `run()`，向后兼容。

#### 3c. `formatProgressLine` 将 JSON 行格式化为可读文本

```typescript
function formatProgressLine(data: {
  event?: string
  epoch?: number
  horizon?: number
  valLoss?: number
  elapsedS?: number
  line: string
}): string {
  if (data.event === "epoch_end")
    return `epoch ${data.epoch ?? "?"} | h${data.horizon ?? "?"} | val_loss ${data.valLoss?.toFixed(4) ?? "?"}`
  if (data.event === "stage_start")
    return `→ stage: ${data.line}`
  if (data.event === "timeout")
    return `timeout after ${data.elapsedS?.toFixed(0) ?? "?"}s`
  if (data.event === "smoke_eval_done" || data.event === "artifact_ready")
    return data.line
  return data.line   // fallback: 原始行
}
```

## 4. 实施顺序

```
Step 1  process.ts 新增 runStreaming          ← 纯工具函数，无副作用，可独立测试
Step 2  event.ts 新增 RunnerProgressLine      ← 类型定义，无运行时影响
Step 3  service.ts 接入流式读取 + 发布事件    ← 核心改动，需要手工测试训练流程
Step 4  cockpit-data.ts 加入刷新事件类型      ← 一行改动
Step 5  cockpit.tsx 接入显示逻辑              ← TUI 渲染，需要 verify-ui 验证
```

每步均可单独提交，Step 1-2 无需真实 runner，Step 3-5 需要实际跑一次 smoke 验证效果。
