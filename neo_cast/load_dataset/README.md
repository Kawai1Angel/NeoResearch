# Dataset 解读

## 1. 这是什么数据

当前 `dataset/` 目录下只有一个文件：

- `load.csv`

从字段和数值分布看，这是一份**小时级负荷预测数据**：

- 主目标列是 `LOAD`
- 时间列是 `TIMESTAMP`
- 还有 25 个外生特征 `w1 ~ w25`
- `ZONEID` 目前只有一个取值：`1`

因此，这个数据集更适合被理解为：

**单区域、单目标、带 25 维辅助特征的小时级时间序列数据集**

## 2. 表结构

`load.csv` 一共 28 列：

1. `ZONEID`
2. `TIMESTAMP`
3. `LOAD`
4. `w1`
5. `w2`
6. `...`
7. `w25`

可以把它分成三类：

- `ZONEID`：区域编号
- `TIMESTAMP`：时间戳
- `LOAD`：预测目标
- `w1 ~ w25`：外生协变量

## 3. 数据规模

基础统计如下：

- 总行数：`15456`
- 列数：`28`
- 区域数：`1`
- 缺失值：`0`

在正确解析时间戳后，这是一条**完整连续的小时序列**：

- 起点：`2008-12-22 01:00`
- 终点：`2010-09-27 00:00`
- 总小时数：`15456`

这说明它不是按样本窗口切好的监督学习表，而是**原始时序表**。

## 4. `TIMESTAMP` 是这个数据里最需要注意的地方

原始时间戳长这样：

- `12222008 1:00`
- `1102009 0:00`
- `112009 0:00`

它的问题是：

- 月和日**没有统一补零**
- 不能直接放心交给普通 `%m%d%Y %H:%M` 解析

例如：

- `1102009` 直觉上应读作 `1/10/2009`
- 但很多标准解析器会把它误读成 `11/02/2009` 或其他歧义形式

更稳妥的读法是：

- 年：最后 4 位
- 月日：前面的 2 到 4 位
- 月、日都允许 1 到 2 位
- 再结合时间连续性去消歧

换句话说，这个数据在建模前最好先做一次**标准化时间戳清洗**。

## 5. `LOAD` 列可以怎么理解

`LOAD` 看起来就是该区域在对应小时上的负荷值，数值为连续实数。

基础统计：

- 最小值：`64.4`
- 最大值：`315.6`
- 均值：`155.54`

从序列模式看，它有很明显的时间结构：

- 日内低谷大约在 `04:00`
- 日内高峰大约在 `19:00`
- 月均值最高在 `8 月`
- 月均值最低在 `4 月`

这说明它同时带有：

- 明显的**日周期**
- 明显的**季节性**
- 一定程度的趋势/节假日/天气驱动变化

## 6. `w1 ~ w25` 是什么

本地目录里没有额外元数据，所以**无法从仓库内证据精确确认**这 25 列的真实语义。

但从命名和数值范围看，它们很像一组外生观测变量，常见解释包括：

- 多个天气站观测值
- 多个相关传感器读数
- 一组同时刻的辅助环境变量

目前能确认的是：

- 一共有 `25` 个外生特征
- 数值大多是整数或接近整数
- 取值范围大致在 `4 ~ 102`
- 与 `LOAD` 同步按小时记录

因此，在没有额外说明文档时，最稳妥的说法是：

**`w1 ~ w25` 是 25 维同步外生协变量，具体物理含义未知。**

## 7. 这个数据适合做什么任务

最直接适合的任务有：

- **单变量时间序列预测**
  只用 `LOAD` 历史预测未来负荷

- **多变量时间序列预测**
  用 `LOAD + w1~w25` 一起预测未来负荷

- **短期负荷预测**
  例如预测未来 1 小时、24 小时、48 小时

- **带外生变量的时序建模**
  例如 Transformer、PatchTST、DLinear、TimesNet、iTransformer 一类模型

## 8. 不太适合什么

它不太适合：

- **跨区域建模**
  因为只有一个 `ZONEID`

- **严格的多实体面板建模**
  没有多个用户/区域/站点

- **需要强语义解释的因果分析**
  因为 `w1 ~ w25` 的含义目前不清楚

## 9. 建模前建议先做的预处理

如果后续要拿它做实验，我建议先做这几步：

1. 先把 `TIMESTAMP` 统一清洗成标准 `datetime`
2. 检查并固定采样频率为 `1H`
3. 按时间顺序切分 train / val / test，不要随机打乱
4. 明确 `w1 ~ w25` 是不是未来可用特征
5. 视模型需要，对 `LOAD` 和 `w1 ~ w25` 分别做标准化

第 4 点尤其重要：

- 如果 `w1 ~ w25` 在预测时刻的未来值不可得，那么它们不能被直接当作已知未来协变量使用
- 如果它们是历史可观测变量，则可以作为 encoder 输入

## 10. 一个简明结论

这个 `dataset` 本质上是一个：

**单区域、小时级、以 `LOAD` 为目标、附带 25 维外生协变量的负荷预测数据集。**

它的优点是：

- 数据完整
- 时间连续
- 周期性明显
- 非常适合做 TSF baseline

它的主要注意点是：

- `TIMESTAMP` 编码不标准
- `w1 ~ w25` 的真实含义在当前目录里没有元数据支撑

如果后面你要基于这个数据继续做实验，建议先单独生成一个“清洗后的标准版本”，把时间列先规范掉。
